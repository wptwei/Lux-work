# 架构评估与调整说明

## 结论

原项目方向正确，已从“红线演示脚本”扩展为具备网页、技能、提示词库、文件处理和输出动作的应用原型；但原版本不适合直接接入部门多人使用。本次调整将它收敛为可控的本地试点版本。

## 本次关键调整

| 层级 | 原状态 | 调整后 |
|---|---|---|
| 模型 | 默认 DeepSeek，断网不可用 | 默认 Ollama 本地模型；公网必须显式启用 |
| 红线 | 只扫描用户 prompt | 用户输入与系统提示词一起扫描；本地/公网分流 |
| 文件 | 先读取，后在发送时判断 | 文件名与大小先检查，内容解析后再检查 |
| 审计 | 日志保存输入/输出前 200 字 | 仅元数据、分类、长度、摘要哈希 |
| 邮件 | 连点两次即可发送 | 对收件人、主题、正文生成确认指纹，变更即失效 |
| 访问 | 默认对全局网卡开放且无认证 | 默认仅本机；局域网模式强制账号密码 |
| 稳定性 | 模型错误直接打断界面 | 面向用户返回可读错误；设置超时和输入上限 |
| 数据库 | SQLite 默认模式 | WAL、忙等待、字段长度与分类校验 |
| 工程化 | 打包整个 `.venv`，无测试 | 依赖清单、安装脚本、健康检查、自动测试、干净交付包 |

## 当前请求链路

1. 用户选择岗位技能并提交文字/文件。
2. 文件接入闸门先检查文件名、扩展名和大小；解析后检查内容。
3. 红线守卫扫描系统提示词与用户输入。
4. 高敏内容直接拒绝；公网模式对可脱敏实体替换为占位符。
5. 模型仅通过统一提供方入口调用。
6. 模型输出再次扫描；合格后按需还原占位符。
7. 审计日志只写元数据；用量进入 SQLite 看板。

## 推荐阶段路线

### P0：单机验证（当前）

- 3–5 名种子用户，使用本地模型。
- 每个岗位挑 3 个高频、低风险任务。
- 记录成功率、人工修订时间、误拦截/漏拦截，不接生产系统。

### P1：部门内测

- 专机部署，局域网认证，IT 防火墙白名单。
- 增加用户与角色（使用者、模板管理员、审计员）。
- 提示词变更审批、数据库每日备份、规则版本号。

### P2：系统集成

- 仅对“读取类”系统先做只读接口。
- 任何邮件发送、工单提交、开关岗等写动作采用预览、审批、幂等键和审计。
- 生产动作与普通对话进程隔离，使用最小权限服务账号。

## 尚未完成的生产项

- 企业统一身份认证与细粒度 RBAC。
- 企业级 DLP、恶意文件扫描、上传文件隔离区。
- 多机部署、任务队列、集中监控、备份恢复演练。
- 模型质量评测集、提示词/规则版本管理和回滚。
- 与门禁/监控/排班等系统的正式接口及审批流。
