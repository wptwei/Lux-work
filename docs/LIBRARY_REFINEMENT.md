# 页面专项 03 — 智能文件库

## 本轮实现
- 继续使用现有资源中心，不新增平行文件库。顶部文件库标题、搜索和上传；岗位模板、历史版本和回收站保留折叠入口。
- 56px 基础行高的深色列表：名称、PDF 类型、大小、最新版本上传日期、操作；长名称或匹配说明可自然增高。统一 24px 线形文件图标，细分割线和整行 Hover；默认仅显示打开，下载收纳于更多菜单。
- 上传按钮展开原入库表单，保留分类、标签、去重和文件解析处理。等待上传、上传处理、成功、失败、重新选择上传均关联真实事件。失败后原缓存按原流程清理，需要重新选择文件；不伪造自动重试成功。
- 文件预览复用现有同源鉴权下载接口，变为右侧不透明抽屉；保留关闭、下载、错误及重试。窄屏使用全宽预览，列表内部可横向滚动。
- 文件库搜索与 AI 对话复用 core/library_retrieval.py，先查现有文件元数据和 PDF 正文索引，再按需调用配置的模型选择真实候选。结果分别说明关键词命中或 AI 元数据候选；模型不可用时如实提示。

## 能力边界
现有 AI 匹配基于文件名、分类、标签，从最多 20 个经过本地排序的目录候选中选择，最多返回 8 份；不是全文向量检索。正文索引用于关键词检索，没有文字层的扫描 PDF 未在本轮新增 OCR。回收站仅用原搜索逻辑，不让模型访问已删除文件。分类隐藏字段及原权限规则保留。

## 修改文件
- app.py：列表渲染、共享搜索入口、上传状态包装、顶部上传按钮及展开/收起；修复初始空查询 None 导致的首屏失败。
- core/library_chat.py：安全转义的列表 HTML，结构化文件元数据与操作。
- core/library_retrieval.py：增加可选结果渲染函数；默认仍输出原对话结果，检索算法不另建一套。
- core/pdf_library.py：目录查询读取已有文件大小和版本上传时间字段；无数据库迁移。
- core/ui_theme.py、frontend/library.css：接入文件库专用主题层，全部颜色引用已有 Design Tokens。
- frontend/workspace.js：现有预览窗口按入口切换为文件库右侧抽屉。
- tests/test_library_workspace.py、tests/test_library_ui.py：渲染、权限边界、共享检索、初始查询和上传失败状态验证。

## 数据保护与验证
测试在隔离副本和临时账号/文件库运行，没有对用户本机数据库做写入。原有文件和上传源文件的字节前后相同，下载取得真实 PDF 字节。回归覆盖有效上传、无效 PDF 失败、重新上传、正文关键词、模型候选选择、预览失败重试、对话调取、匿名下载拒绝及普通用户上传入口限制。

37 项文件库/检索测试及 4 项界面回调测试通过。浏览器验收记录随包提供；模型选择使用隔离替身，不代表用户本机 Ollama 的语义效果。无头浏览器验证 PDF 字节、Blob、抽屉和重试，不能证明 Windows 内置 PDF 阅读器的最终分页显示。未在用户 Windows 项目目录部署。
