# 周报 Agent v4.1：内容智能化修复说明

## 1. 问题根因

上一版在模型调用异常、结构化 JSON 解析失败或正文事实核验失败时，会调用本地关键词规则生成完整兜底草稿，并把草稿返回到可编辑正文区域。即使界面显示“兜底草稿”，用户仍可能继续将其导出为正式 PPT。规则分类不能替代语义创作，因此会出现人力/事件错位、原始写作指令泄漏、数据页缺少分析等问题。

## 2. 模型调用策略

- 阶段一：模型返回结构化策划，包括页面类型、标题、用途、来源事实 ID、缺失字段与视觉计划。
- 阶段二：封面、目录、结束页采用稳定模板；其余业务页逐页调用模型，减少长文本一次性输出导致的截断。
- 单页生成若出现跨页标记、提示词泄漏、无来源数字/趋势/原因或不允许的图表数据块，最多修复重试一次。
- 模型服务失败、策划无效或页面校验失败时，不生成可导出的正文；只保留事实分类/策划诊断并说明失败阶段。

## 3. 素材分类改进

- 拆分 `①/②/③` 等明确章节标记、分号分隔的指标，以及同一行中“人力指标 + 日期事件”的组合。
- “楼栋/岗位/人力”与“日均通行/违禁品/垃圾检查工时”等字段分开分类。
- 日期匹配增加字母数字边界，避免把 `H1-3F` 错认成日期。
- “所服务 BU”等背景信息归入 context，不作为本周工作。
- “下周计划的具体详细内容你帮我写”等写作指令会被过滤，不进入事实清单。

## 4. 内容质量闸门

正式导出前检查：

- 页面编号、页数、空白页与超长正文；
- “你帮我写”“按日期：谁、干了什么、结果”等指令或模板提示；
- `【待补充：...】`、TODO/TBD 和未确认的统计周期；
- 有来源状态时，检查数字、趋势和原因能否回溯到当前页事实；
- 图表对比是否有同一指标的本期/上期原始值，图表标签和数值是否出现在来源素材中。

## 5. 验收结果与限制

当前开发环境中 128 项自动化测试通过，包含对模型异常、逐页创作、事实拆分、指令过滤、图表值核验和导出拦截的测试。测试使用模拟模型响应；真实 Windows + Ollama 的调用成功率、延迟与最终页面质量仍需用户本地验收。
