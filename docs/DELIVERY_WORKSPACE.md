# 页面专项 04 — 交付中心

## 架构审查与信息减法
现有交付中心的主要任务是整理工作素材、逐页生成周报草稿、确认后导出 PPT/Word，以及本机 Word 转 PDF。交付物台账保存文件名称、类型、版本、大小、生成时间和所有者，不保存历史草稿；没有独立任务优先级、截止日期或人工状态修改流程。

主界面改为个人交付记录列表：类型筛选、刷新记录、新建交付。表头 40px，数据行 56px；默认只展示详情操作。台账读取本人最近 100 条记录，文件不可用记录优先，其余按原时间顺序显示；“已生成/文件需核查”由原文件是否存在得出，不等同于业务审核完成。

原有素材输入、文件导入、模板选择、草稿编辑、策划检查和导出控件全部保留，集中在“制作与导出”折叠区；新建交付打开该区域。Word 转 PDF 仍保留为低频折叠工具。没有删除原业务依赖。

## 详情与状态
原页增加右侧详情抽屉，展示编号、名称、类型与版本、真实生成时间、关联文件名、文件大小及可用性。支持关闭、Escape、焦点恢复，直接打开同页制作区。

历史台账仍仅保存元数据，不新增历史文件下载接口，也不能恢复历史草稿；本次会话的真实 PPT/Word/PDF 下载按钮保留在制作区。没有虚构截止时间、审批节点或可手动编辑的交付状态。

逐页生成进度仅在原业务状态包含 completed_pages/total_pages 时显示细线 progress；模型分析阶段只显示说明，不显示虚假百分比，失败和完成后收起进度条。

## 修改文件
- app.py：交付记录列表、类型筛选、刷新、同页制作入口、只读详情内容、真实进度展示与更新绑定；生成、导出、转换的业务函数未改变。
- frontend/delivery.css：深色列表、56px 行高、克制状态色、右侧抽屉、窄屏列表内部滚动与次级操作降色。
- frontend/workspace.js：详情抽屉打开/关闭、焦点返回和打开制作区。
- core/ui_theme.py：加载新样式层，沿用全局 Design Tokens。
- tests/test_delivery_workspace.py：本人数据隔离、安全转义、文件缺失状态、类型筛选及真实进度检查。

## 验证结果
34 项相关测试通过，包含版本台账、PPT 管线、周报导出、Word 转 PDF 相关逻辑和新列表/进度测试。
浏览器实际生成并下载了 Word 与 8 页 PPT，检查了 ZIP 结构、Word 正文、PPT 页数以及导出后的记录刷新。还验证了类型筛选、关联文件展示、缺失文件提示、抽屉键盘关闭、同页制作、无效草稿被拦截及窄屏无整页溢出。完整记录随包提供。
结构比较确认 8 个关键业务函数未变：export_ppt_workspace、export_word_workspace、run_word_pdf、stream_structure_ppt_source_ui、_structure_ppt_source、refresh_weekly_preview、inspect_delivery_template、ingest_attachment。数据库和业务 API 无迁移。

## 待处理与验证边界
测试在隔离 Linux 副本和临时台账中进行，没有部署到用户 Windows 目录。真实模型生成质量与 Microsoft Word 转 PDF 尚需在本机确认；浏览器导出使用固定的有效草稿，实际文件生成没有用模拟成功替代。测试中的两条初始台账记录是隔离样例，不会写入用户数据。
如果未来需要截止日期、人工任务状态、跨会话恢复草稿或历史文件鉴权下载，应作为单独业务需求设计，本轮没有擅自添加这些流程。
