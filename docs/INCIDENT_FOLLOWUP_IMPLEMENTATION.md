# 异常记录：即时反馈、关键事实补问、当前记录更正

日期：2026-11-05。此次已修改实现，不是仅提供方案。未重启正式服务，未向正式台账写测试记录，无新增数据库迁移。

## 使用方式

1. 在“异常记录”提交描述。数据库提交后，页面先显示“已记录，正在匹配”，随后更新条款。编辑保存和补问答案同样分两阶段反馈。匹配失败仍保留事件；浏览器中途断开后持久任务仍可由既有 worker 恢复。
2. 如果存在影响匹配的关键缺项，只提出一个问题。例如“供应商没人陪同，保安已经拦住了”会询问人员是在进入前还是进入后被拦住。可在详情填写答案，或在同一页面的聊天/语音助手直接回答“没进去”。答案追加到同一事件并留痕，不新建事件。
3. 可点击“跳过补问”，或回答“跳过 / 不清楚”。不会推断未知事实，不影响原记录。普通话题开始后，未回答的补问结束，避免之后一句短答误修改旧事件。
4. 登记成功或在列表中打开本人记录后，可在同一页面的语音助手中说：
   - “刚才地点说错了，改成北门”
   - “刚才那条的时间改成14:30”
   - “再补充一句，现场已经清理”
   - “刚才那条记录全文改为：……”（明确替换全文）
5. 更正生成新版本并自动重新匹配，旧正文、旧条款和动作记录保留。地点/时间修改只在能确定目标时执行；存在多个地点或时间时提示使用全文编辑。

## 范围与边界

- 当前记录按登录用户和 Gradio 浏览器页面会话隔离，15 分钟过期。刷新、新页面、服务重启后需要重新打开记录；不会从账号最近一次记录猜测目标。
- 清空聊天或新建记录会清除当前目标。打开他人记录不会留下先前可编辑的目标。
- 相对更正和补问答案校验当前事件版本，并在数据库事务内再次检查；其他操作已修改时提示重新打开，防止覆盖。
- 本期使用确定性规则选择与解析问题，支持进入情况、陪同情况，以及实际候选规则中缺失的历史次数条件。不会对每条报告机械追问时间/地点，也不支持任意自然语言自动改写所有字段。
- 界面保存回执先于匹配返回；语音沿用已有回答完成后的 TTS 播报流程。真实麦克风和播放延迟仍需真机验收。
- 修复回答完成事件的投递对象：发送到 `document`，与现有语音输出/对话监听保持一致。
- 没有加入主管审批、自动扣款或发奖。

## 改动文件

- `core/incident_conversation.py`：短期当前事件上下文、单项补问、保守语音指令解析。
- `core/incident_intake.py`：可选 expected_version 的事务校验，提交重试额外校验操作和目标。
- `app.py`：两阶段表单反馈、聊天/语音补问与更正、详情回答及跳过按钮、会话清理、播报事件修正。
- `frontend/incident_record.js`：手动聊天同样携带稳定提交编号，补问提交使用独立编号。
- `tests/test_incident_followup.py`、`tests/test_incident_record.cjs`：针对事务、版本、会话隔离及前端事件的新增测试。
