# 红线守卫实际行为说明（更正《安全红线报告 v0.6》）

> 本文只描述代码的真实行为，用于更正报告中与实现不一致的说法。
> 依据：`core/redline_guard.py`、`config/redline_rules.json`、`tests/test_core.py`。

## 1. 更正：六个“直接拦截”词并不拦截

报告称“监控画面、监控截图、厂区布局、完整花名册、门禁原始记录、带公司抬头原件”六类内容会被直接拦截。
**实际不是这样**：`config/redline_rules.json` 中 `block_terms` 为空，这是有意设计——
`tests/test_core.py` 明确要求“请制定监控画面和厂区布局资料的管理制度”这类正常讨论**不能**被拦截。

这些词目前只在**上传文件/图片**时作为复核线索，并且需要多条线索同时出现才会进入人工复核（`review`），
单独一个词、纯文字输入不会触发。

## 2. 四个处理级别

| 级别 | 触发 | 结果 |
|---|---|---|
| `block` | 身份证号、手机号；`block_terms` 命中（当前为空） | 拒绝，不送模型；日志只记类别 |
| `review` | 上传文件/图片命中多条受控资产线索 | 进入人工复核队列，原文件复制到 `data/review_files/` |
| `desensitize` | 客户名、区域名、单位名、工号 | 替换为占位符后再送公网模型（本地模式不替换） |
| `allow` | 以上都不命中 | 原样放行 |

模型输出复检使用普通文字扫描，不含文件资产线索，因此实际只会因身份证号、手机号（以及 `block_terms` 若有内容）拦截。

## 3. 第 1 步补丁之后新增的出口检查

以下“送出系统/落盘成文件”的路径现在统一经 `RedlineGuard.check_outbound()`：

- 邮件外发（主题 + 正文）：命中 `block` 即拒绝发送。
- 周报 PPT / Word 导出：对人工编辑后的周报全文检查，命中 `block` 即拒绝导出。
- Word 转 PDF：转换前先检查文件名和正文（`ingest_word_for_conversion`）；旧版 `.doc` 无法读取正文，不放行，需另存为 `.docx`。

脱敏级内容（部门名、区域名）在内部邮件和周报里属正常内容，不拦截。

- 新增的 Word 转换闸门最大读取 50 MB 的 `.docx`；超大文件会被拒绝。
