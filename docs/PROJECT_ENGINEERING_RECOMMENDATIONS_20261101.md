# LUX 项目整体工程建议

评估日期：2026-11-01。依据当前源码、部署配置和本会话中的实际故障诊断；本轮未修改业务代码、运行回归测试、重启服务或做完整安全审计。

## 总体判断

项目已有明确业务场景、账号权限、资料库、模型接入、文档产出、审计和发布机制，适合继续做部门小范围试点。下一阶段应以可验证的业务正确性、稳定运行和故障恢复为主，控制新增功能数量。

已具备会话任务状态、上下文意图路由、本地与公网综合检索、数据库迁移、SQLite 备份与回退脚本。后续改进基于这些实现，不重新建设一套平行系统。

## 产品与质量

先把三条高频流程做成可验收闭环：

1. 资料查找与有依据的问答：找对文件、读到相关正文、显示来源、无依据时如实说明。
2. 通知和情况说明的连续修改：继承约束、理解纠正、保持事实、可继续编辑。
3. 周报生成与交付：事实可追溯、数字一致、文件可打开、导出版本对应当前内容。

每条流程明确输入、输出、必需信息、权限、成功条件与失败后的恢复操作。界面简化为主要任务入口加统一对话区，运行诊断放管理页。

建立 30–50 条脱敏真实案例，包含动作区分、否定、纠正、指代、任务切换、无结果、错误来源、文件权限和同账号多会话。保留未参与提示词调试的测试案例；版本发布前后跑同一套评测。

模型更换先固定输入、上下文和证据，再比较任务完成率、约束保留率、引用支持程度、延迟和资源占用。较大显卡提升计算能力，不自动修复缺失知识、错误路由或被裁剪的要求。

## 知识与来源

- 内部制度、用户素材、外部网页和模型推断分别标识，冲突时展示依据、版本和不确定性；公网资料不覆盖内部受控制度。
- 当前综合检索已经能读取本地正文，不应把项目描述为仅能返回文件卡片。下一步优化相关段落召回、证据范围和引用支持度。
- 检索和正文读取都保留权限检查。向量检索若后续引入，必须在权限允许的集合中召回，缓存也要考虑用户权限和文件版本。
- 不先为此新增向量数据库。先用真实案例验证现有全文检索、分段、排序、文档版本与 OCR 质量，确认瓶颈后再加语义召回。

## 运行与架构

继续采用模块化单体：界面层 → 业务服务 → 模型/语音/检索适配层 → 数据与文件存储。现阶段保留 Gradio 和 SQLite；仅在并发、移动端交互或部署需求确实超出能力时再迁移技术栈。

耗时的语音、周报与文档转换应有明确任务状态、超时、排队反馈、取消和资源上限。按模型资源调度，避免 CPU/GPU 过度并发；独立 worker 是可以逐步增加的运行单元，不等于立刻拆成多个微服务。

健康检查分层：

- 进程/存活：服务能响应。
- 就绪：数据库、模型和必要资源可用。
- 公网入口：外部地址能到达预期登录页，匿名受保护接口仍被拒绝。
- 业务探测：使用隔离测试账号及非敏感样例验证关键链路，不在每次探测自动产生付费请求或外发业务材料。

日志关联 task_id / conversation_id / request_id，记录阶段、状态、耗时和错误类别。默认继续不保存业务原文、音频、密码、模型提示词或完整网页。不要向前端展示内部路径和原始异常。

当前语音、模型、搜索和公网隧道分别展示状态，避免把“模型在线”当成“整个系统正常”。

## 发布与数据

在现有 deploy/、迁移和备份基础上执行统一流程：测试 → 标记版本 → 备份 → 发布 → 迁移 → 启动 → 本机与公网验证 → 失败回退。

建立独立试运行实例，使用隔离数据与端口；避免同事试用的生产实例成为临时调试对象。核对生产环境变量、部署配置、实际进程与日志所属版本。

备份已经使用 SQLite backup API，应保留该设计。继续完善文件原件、配置、版本清单的一致性，备份放置独立副本，并定期在隔离位置恢复；验证库可读、文件可开、文件版本和权限一致。不要在生产目录里演练覆盖恢复。

公网使用维持强密码、个人账号、下载鉴权和最小暴露面；Ollama 和数据库不直接对外开放。后续增加账号管理、文件权限或新接口时，同步补跨用户访问测试。

## 建议里程碑

以下是工作顺序，具体工期需按实际实现与验收调整。

| 阶段 | 重点 | 可验收结果 |
| --- | --- | --- |
| 第一阶段 | 单一服务托管、端口统一、公网状态、会话隔离、制度边界 | 同事能稳定进入；健康检查对应正确实例；手机电脑任务不串；无条款时不伪称制度依据 |
| 第二阶段 | 真实案例集、相关正文召回、连续修改、语音分段 | 对比原版能证明完成率或延迟改善，而不是只增加接口 |
| 第三阶段 | app.py 渐进拆分、资源调度、移动端流程 | 一处改动影响范围缩小；长任务可恢复；两用户并发有明确反馈 |
| 第四阶段 | 统一发布验收、恢复演练、模型/硬件对比 | 每版有指标、有恢复证据；依据测量决定下一步投入 |

首批交付建议限定为：部署与会话隔离修复、健康检查修复、真实评测集和对应回归。暂不同时引入多个新框架、模型或数据库，以便判断变化的效果。
