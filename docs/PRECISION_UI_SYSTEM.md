# Precision UI System 实施与验收

本轮针对已有九页工作台做公共组件精修。沿用 Gradio 6.28 与原有页面；没有创建平行页面。交付物是项目覆盖包，尚未安装到用户的 Windows 电脑。

## 实际修改

| 文件 | 修改与视觉效果 | 功能影响 |
| --- | --- | --- |
| `frontend/design_tokens.css` | 增加按钮 32/40/44px、输入框 44px、表头 40px、数据行 56px、深蓝选中背景、蓝色 Hover、遮罩与焦点环变量 | 仅设计变量 |
| `frontend/precision.css` | 公共操作按钮尺寸与状态、Ghost、输入焦点/错误/禁用、表格行状态、空状态、弹窗三区结构及减少动效规则 | 消费真实状态，不生成业务结果 |
| `frontend/workspace.css` | 导航使用深蓝选中背景；普通卡片 12px；统一表格尺寸；修正主按钮 Hover；修复 Gradio 对部分 `:is()` 选择器的处理冲突 | 保留导航与原有组件 |
| `frontend/workspace.js` | 为真实操作按钮附加公共样式类；不覆盖折叠标题与整行入口；PDF/交付抽屉使用公共头部与操作区；文件“更多”菜单支持 ESC 收起 | 保留原来的回调、预览请求、原生对话框焦点管理与焦点返回 |
| `frontend/library.css` | 文件列表表头、行高与行内按钮使用统一尺寸变量 | 上传、搜索、预览、下载逻辑不变 |
| `frontend/delivery.css` | 统一台账尺寸、详情按钮及遮罩变量 | 交付业务不变 |
| `frontend/assistant.css` | 去除早先重复的用户消息样式规则，保留后面的完整定义 | 对话与语音逻辑不变 |
| `core/ui_theme.py` | 在现有主题加载序列中接入公共组件状态层 | 所有页面复用同一套规则 |
| `tools/check_ui_styles.py` | 增加可重复执行的 CSS 解析、完全重复规则、主题外颜色字面量审查 | 仅开发检查工具 |

现有 Small/Large 参数分别映射 32/44px；原生普通操作按钮使用 Medium 40px。文本域保留业务所需多行高度；导航项、可展开标题、整行工作入口、原生文件选择器不强制压成普通按钮。表格 56px 是常规行高，长内容仍可自然增高，窄屏表格内部横向滚动。

## 合并依据和必须保留的差异

- 主按钮样式只跟随真实 `primary` 类型，不再把交付区同一业务类中的次要按钮一起染成主色。
- 按钮尺寸和状态归入公共组件规范；列表行内操作用 Small，原有大操作用 Large，普通图标操作用 Medium。
- PDF 预览与交付详情复用标题区、遮罩和操作区；PDF 保留可读预览主体，交付保留元数据滚动主体，宽度仍按场景区别设置。
- 录音中的警告色、真实识别状态、AI 核心输入焦点效果继续保留，不用普通按钮规则掩盖业务状态。
- 用户消息的重复定义删除一处。CSS 审查未发现完全相同的重复规则；同一选择器在不同响应式条件或页面层出现，不直接视为可删除的重复实现。
- 旧 `lux.css` 仍作为布局兼容层保留，未对其所有历史规则做大规模清除。本轮验证的是公共组件的最终呈现与相关业务；不宣称已删除全部旧 CSS。

## 运行检查和结果

环境：隔离的 Linux 项目副本、Gradio 6.28.0、Chromium/Playwright。测试账号和测试文件只存在于隔离目录。

| 检查 | 结果与边界 |
| --- | --- |
| 九页公共 UI | 95 项通过：1440/1024/390px、无页面横向溢出、单一导航选中、按钮尺寸、232/68px 导航、表格高度、蓝色主操作、焦点样式、抽屉键盘关闭和焦点返回、减少动效、无 JS 异常 |
| 文件库浏览器回归 | 21 项通过：真实测试 PDF 上传、失败后重选上传、内容索引搜索、预览原件、下载、预览失败重试、原文件字节保持、权限边界、对话调取、手机布局、抽屉底部下载入口可见 |
| 交付浏览器回归 | 18 项通过：个人记录隔离、缺失原件提示、详情、回到原制作区、无效草稿拒绝、真实 Word/PPT 导出下载、版本记录和类型筛选、手机布局 |
| Python 相关自动化测试 | 107 项通过：交付、文件库、助手、语音等现有相关测试。出现已有未关闭 event loop 的 ResourceWarning，不影响本次测试通过，但仍值得后续排查 |
| 语音采集脚本 | Node VM 模拟 Web Audio 测试通过：麦克风轨道释放、尾部采样、手动编辑保留、迟到结果忽略、不自动发送等；不等同于实体麦克风验收 |
| 对比度 | 既有 33 组主题颜色对比度检查全部通过；不将它等同于每一个第三方控件组合均经过人工无障碍审计 |
| 样式静态审查 | 8 个已加载样式文件无解析错误、无完全相同规则；颜色字面量集中在 Token 文件，其他已加载 CSS 为 0 |
| 语法与业务保护 | Python 编译、工作台 JS 语法通过；`app.py` 和 `voice_input.js` 与本轮修改前逐字节相同 |

测试中实际发现并修复了两类冲突：Gradio 对部分 `:is()` 选择器的作用域处理导致焦点样式被盖住；旧全局 `footer` 隐藏规则导致新抽屉操作区不可见。两项均在修复后重新测试；交付“打开制作区”及 PDF 底部下载入口已通过浏览器验证。

## 可在项目目录复查

```powershell
.\.venv\Scripts\python.exe -m pip install tinycss2
.\.venv\Scripts\python.exe tools/check_ui_styles.py
.\.venv\Scripts\python.exe tools/check_design_tokens.py
.\.venv\Scripts\python.exe -m unittest tests.test_delivery_workspace tests.test_library_workspace tests.test_assistant_ui tests.test_voice_input -q
```

`tinycss2` 只用于静态检查，运行工作台不需要新增它。

## 保留能力和本机待验证项

- 未改变 API 协议、数据库结构、文件内容、账号权限或交付业务流程。未用前端假成功替代接口结果。
- 模型选择、聊天回复在浏览器回归中使用确定性测试替身；真实 PDF 数据、上传、文件接口和内容索引正常执行。尚不能据此保证本机 Ollama 的回答质量或可用性。
- 物理麦克风权限与本地 ASR、Windows Office/COM 转 PDF、本机模型需要在用户电脑上验证。Safari/Firefox 与屏幕阅读器尚未覆盖。
- 预览和交付详情是只读抽屉，关闭不会丢弃编辑，所以不新增关闭确认。原有业务确认仍保留。
- 后端未提供的能力不在本轮虚构：文件库不是完整向量语义检索；交付台账不会从历史记录还原草稿。
