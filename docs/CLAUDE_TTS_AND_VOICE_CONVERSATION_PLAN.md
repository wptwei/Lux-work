# 给 Claude：网页前台唤醒与多轮语音助手方案

日期：2026-11-03。本轮已检查当前源码及官方 TTS 文档；尚未安装 TTS 模型、调用付费 API、修改业务代码或重启服务。

## 0. 用户已确认的范围：网页前台语音唤醒

用户明确希望像小艺、小爱同学、Siri 一样，呼唤名字后进入语音对话，并已选择：打开助手网页、主动开启麦克风后，在网页前台进行语音唤醒。

本任务的最终验收必须包含真实唤醒与对话闭环。下方回答朗读是内部基础里程碑，不能只交付朗读按钮便宣称任务完成。

### 使用流程

1. 用户登录 HTTPS 页面，点击“开启语音助手”，授权麦克风并解锁浏览器音频播放。
2. 浏览器本地等待唤醒词。默认暂用“小安小安”，配置可更换；需生成该关键词对应的模型 token，不能认为随意更改字符串就一定能识别。
3. 检测到唤醒词后播放“我在，请说”或提示音，界面展示正在聆听，进入有时限的录音轮次。
4. 用 VAD 判定用户开始讲话和停顿结束，识别为文本，进入现有登录用户的对话上下文，再调用现有模型/工具。
5. 模型回答通过检查后进行 TTS，在用户当前设备播放，界面同步保留文字。
6. 播放结束后可提供一个有限的追问窗口，无需每轮重复唤醒；超时或“再见/结束对话”后回到本地等待唤醒。
7. 点击关闭、离开页面或会话失效时停止采集与播放，并清理任务。页面隐藏后首版暂停，恢复时给出明确的重新启用操作。

### 端侧唤醒候选及部署

- 优先验证 sherpa-onnx 中文 KWS + WebAssembly + Web Worker。官方仓库含 `wasm/kws` 示例和中文模型准备说明。
- 第一个里程碑是在真实手机浏览器验证中文唤醒，不是直接移植服务器 Python 麦克风示例。模型、字典、tokens、关键词和运行时必须匹配。
- 唤醒词检测发生在正在使用网页的手机或电脑。服务器的麦克风不能代替远程手机麦克风。
- 未唤醒时默认不向服务器持续上传环境音频，也不运行完整 Whisper 来不停转写环境声音。
- 必要资源由本应用受控提供并缓存，校验版本；注意 WASM 加载路径、MIME、CSP、Worker 与手机浏览器能力。若构建依赖 SIMD、线程或 SharedArrayBuffer，要检测兼容性并提供可用降级，不能假设 Gradio 公网域名默认满足跨源隔离。
- 可以在端侧保留短而有限的内存环形缓冲，避免“小安小安，帮我……”连续说话丢掉问题开头；定义唤醒后的最小上传范围，禁止把长时间环境录音补传到服务端。
- 唤醒音尽量使用预合成短音频，减少首次响应等待。提示音兜底不能替代最终语音回答验收。

### 轮次和回声

- 状态机扩展为 disabled / loading / armed / acknowledged / listening / transcribing / thinking / synthesizing / speaking / follow_up / error。
- VAD 停顿阈值、等待开口超时、单轮最大录音时长、追问窗口与唤醒冷却期均可配置，按真实中文讲话测量后选值。
- 首版轮流说话，播放唤醒应答和 TTS 时抑制自身回声触发；不能将扬声器声音当成下一轮用户输入。
- 首版始终提供点击打断；边播边监听的语音打断在回声抑制实测通过后增加，不能声称半双工已经支持自然双工。
- 重复唤醒、电视/同事说到相似词、低音量、噪声与两设备同时唤醒需有冷却、阈值和可见反馈。

### 边界与里程碑

只承诺用户主动开启后的网页前台体验。锁屏、切换 App、关闭网页、系统后台随时唤醒不在本次范围；不能通过安装为 PWA 就承诺获得系统助手能力。

依次交付：A. 手机浏览器中文 KWS 可行性验证；B. 安全 TTS 与播放；C. 唤醒 → 提问 → 回答 → 语音播报闭环；D. 追问窗口、取消与迟到结果隔离；E. 延迟优化及可选语音打断。

不要求先购买服务器或独显。端侧唤醒与服务器 ASR/LLM/TTS 的资源消耗分开评估。用户未选择云端 TTS，首版按本地优先实现，云端调用保持关闭。

## 1. 目标与当前基础

当前已有 `frontend/voice_input.js`、`core/realtime_voice.py`、`voice_asr.py` 提供麦克风输入、分段 PCM 和本地识别；`core/providers.py` 和 `app.py:respond` 提供模型回复。当前未发现完整的 TTS 输出服务和浏览器播放管理。

实现链路：

麦克风 → ASR → 可核对的用户文字 → 当前任务/对话上下文 → 现有模型与工具 → 输出检查 → TTS → 手机/电脑扬声器。

TTS 改善声音；自然沟通还需要简短口语回答、正确承接上下文、明确轮次、低延迟和可停止播放。

按之前检查的 Ryzen 7 / 约 16GB / AMD 集显配置，先测试本地 CPU 可运行的轻量 TTS，不预设必须采购 NVIDIA 显卡，也不承诺达到某个实时速度。

## 2. 模型选择与数据边界

默认按本地优先设计统一接口，但模型最终选择以用户试听、许可证核对和本机实测为准：

- 本地候选：sherpa-onnx + Kokoro 中文多语模型。官方预训练列表包含中文/英文模型与多音色。先核对具体模型、音素前端、音色文件、授权和 Windows 依赖，再下载部署。
- 云端候选：阿里云 CosyVoice，支持 WebSocket 流式合成。用户同意使用后再配置实际地域、业务空间、模型和音色；不假设不同模型与音色通用。
- 需要快速验证播放流程时可提供浏览器 speechSynthesis 适配器，但系统是否有中文音色、是否离线、音质与行为均因设备而异，不能将其宣称为一致或保证离线的生产方案。

云端 TTS 会额外发送待朗读文字，即使聊天模型是本地 Ollama，也属于独立外发通道。必须先过外发检查和脱敏；不可通过“本地模型”开关绕过。用户未选云端时不发起此类调用。

模型下载与语音引擎准备应显式执行，不在用户第一次点击朗读时临时下载。缺少 TTS 或云端凭据时，文字聊天和原语音输入仍可用。

## 3. 分阶段交付

### 第一阶段：安全、可停止的回答朗读

- 每条合成就绪的助手消息提供“朗读 / 停止”，新增默认关闭的自动朗读开关。
- 只合成当前用户有权访问的正常助手回复。第一阶段使用最终通过现有输出检查的文本，不把未完成的模型 token 直接送去朗读。
- 清理 Markdown 标记、代码块、网址和 UI 提示；保持数字、日期、否定和业务含义准确。
- 长报告、表格和制度原文不默认全文播报；语音模式给出简短且有依据的答复，详细内容保留在界面。完整朗读作为明确选择。
- 引用正文保持在界面；语音可说“具体依据见页面来源”，不能凭清理文本产生相反含义。
- 合成失败显示可理解的提示并保留文字，避免卡住发送按钮或整段对话。
- 选择用户可试听的合成音色；界面说明为 AI 合成语音，不默认克隆真人声音。

### 第二阶段：轮流语音对话

- 提供“开启语音对话 / 结束对话”，首版以明确的“说完了/发送”结束用户轮次，保留现有识别文本核对能力。
- 用户主动开启后，ASR final 才可触发聊天；partial 不触发提交。普通听写模式继续只填草稿、不自动发送。
- 流程状态至少包括 idle / listening / transcribing / thinking / synthesizing / speaking / error，状态来自真实事件。
- 加入“打断并说话”：用户点击后立即停止当前播放、清空待播队列、使旧合成结果失效，再开始录音。
- 初版使用轮流说话控制回声；播放期间不把扬声器声音自动作为新用户消息。不能靠一个 echoCancellation 参数承诺回声完全消除。
- 语音输入仅改变输入方式，不能降低文件权限、红线规则或邮件/业务操作的人工确认要求。

### 第三阶段：降低首音延迟与自然打断

- 将已允许输出的模型文本按完整句子缓存，检查通过后送 TTS；不按任意 token、固定字符截断，避免割裂小数、日期、否定和专有名词。
- 语音播出后不能撤回。明确使用句级检查的边界，不把后续全文检查能撤回文字当作能撤回已播放声音。
- 有序播放，限制积压，只允许当前轮次的音频进入播放器；首句产生后即可播放，后续句子并行准备时须有资源上限。
- 本地文件分句合成不等于真正的流式音频合成，要分别报告延迟。云端使用 provider 的正式流式协议，按文档结束任务并完整处理音频尾部。
- 在前两阶段可靠后，才增加 VAD 停顿检测、自动轮次结束与讲话打断。用扬声器、耳机、手机弱网分别验证，处理回声、误触发和噪声。

## 4. 建议代码边界

- 新增 `core/tts.py`：引擎接口、状态、合成结果、长度限制、超时和取消。
- 新增 `core/tts_providers/`：选定的本地适配器；云端适配器按选择另行启用，密钥仅服务端持有。
- 新增 `core/voice_dialogue.py`：轮次状态机，不把全部逻辑继续堆入 app.py。
- 新增 `frontend/voice_output.js`：用户手势解锁播放、播放队列、暂停/停止、打断、页面退出清理。
- 修改 app.py：只连接消息、语音会话状态与控件；复用现有模型、对话上下文和安全入口。
- 音频获取路由复用现有认证体系，响应不包含内部文件路径。
- `core/settings.py`、`.env.example`、单独可选的 TTS 依赖文件、显式模型准备脚本和使用文档。

接口可以统一为 `synthesize(text, voice, speed, task_context)`，返回音频与采样率/格式；原生支持流式的 provider 可以增加 stream 接口，不能让接口设计掩盖实际能力差异。

建议配置字段，名称可调整：

```dotenv
LUX_TTS_ENABLED=false
LUX_TTS_PROVIDER=local
LUX_TTS_MODEL_DIR=
LUX_TTS_VOICE=
LUX_TTS_SPEED=1.0
LUX_VOICE_DIALOGUE_ENABLED=false
```

自动朗读开关和所选音色按用户/会话管理，不用全局变量控制所有人的扬声器。云端缺凭据时明确报错，不偷偷切换另一个服务。

## 5. 会话隔离、音频保护与取消

- 每次合成带 user_id、conversation_id、message_id、generation_id 和片段序号；后端路由根据认证身份确定 user_id，不相信客户端传入的身份。
- 音频播放在请求它的浏览器执行，不在服务器音箱播放。
- 临时音频按用户和会话隔离，访问时重新校验归属；不要把整个音频目录加入公开 allowed_paths。
- 不从客户端接受任意服务器文件路径或任意外部 URL。使用应用生成的音频 ID 与受控存储。
- TTS 缓存如启用，考虑权限范围、模型、音色、语速和版本；不能通过共用缓存泄露其他用户的回答。
- 设置音频 TTL 和清理策略。运行日志只保存 ID、长度、状态与耗时，不默认保存完整回答、原录音、音频内容或密钥。
- 打断、切换会话、开始新回复时，前端立即停止并清队列；后端取消待执行工作，不能安全打断的合成丢弃结果，迟到片段不得再播放。
- 单个 TTS 模型优先受控复用，设置并发和排队上限；Windows 多进程下避免无意为每个用户加载一份模型。

## 6. 手机播放与拟人化交互

- 用户点击“开启语音对话”时建立/恢复播放上下文，并处理 play()/resume() 被拒绝；自动播放受限时显示手动播放按钮，而不是只报告生成成功。
- 显示当前是否在录音/处理/说话，始终可结束；不在页面加载后未经操作自动播报。
- 对话模式使用自然、简短、专业的中文；先直接回应，再按需补充。缺事实时追问一个必要问题，不凭语气模拟出不存在的能力。
- 不默认把表格、URL、代码和长文档逐字读出，也不每轮朗读固定开场白。
- 初版包含第 0 节的前台唤醒，不增加手机锁屏/系统后台常驻录音、数字人、表情识别或真人克隆。

## 7. 实测与验收

- 先对 10–20 条获准的中文短句试听和计时，覆盖数字、时间、制度编号、岗位专有词与中英文混合。
- 对比首音时间、合成实时率、停止讲话到听到回复的端到端时间、峰值内存和 CPU/GPU 占用。分别测预热与冷启动、电脑与手机、本机与公网。
- 原 ASR + Ollama 已有延迟；新增 TTS 后总等待是各阶段之和，不能只测 TTS 就宣称整套对话低延迟。
- 本地候选性能未经验证，不承诺当前电脑可以同时运行所有模型而无排队。模型常驻与并发须在真实设备测试。
- 验证手机浏览器播放受限、网络中断、合成超时、连续点击朗读、打断、换页、两用户并发、旧片段迟到、音频越权访问和临时文件清理。
- 单元测试可模拟音频，但必须另做真实语音试听和手机播放。保留现有登录、上下文、检索、输入框手动编辑和发送逻辑的回归。

按第 0 节里程碑实施，先验证手机浏览器中文 KWS，再完成语音链路。报告真实唤醒测试、试听样例、配置与测试结果；只完成文字朗读时标为基础模块完成。不要在开发过程中直接重启当前公网实例，部署时使用项目统一服务管理流程。

额外验收：正常唤醒召回、误唤醒、唤醒后立即接问题、长停顿、重复唤醒、没有讲话、扬声器回声、连续追问、主动结束、手机切后台后恢复，以及未唤醒时无持续音频上传。Mock 音频事件不能代替真人在手机浏览器的测试。
