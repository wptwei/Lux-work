# LUX 语音超时修复（2026-10-27）

已移除截图中的独立语音面板：不再显示音频上传框、独立转写输入框、“重试上传文件”、“填入输入框”和“收起”按钮。

## 本次超时修复

发现并修复上一版的事件绑定错误：浏览器脚本通过原生 DOM input 事件写入 PCM，但 Gradio 6.28 的 Textbox.input 在该版本随包前端中由 keypress 处理器触发。程序写入值会更新组件并触发 change。因此后端音频接收从 `voice_pcm.input` 改为 `voice_pcm.change`，避免只录音却没有调用接收函数。

此前 Node 模拟只验证了音频脚本，接口测试又直接调用后端，漏掉了框架事件绑定这一环。本次新增了运行中 Gradio 配置的事件目标检查：旧版明确失败，修复版通过。该检查与接口测试仍不等同于用户浏览器的完整真人录音验收。

新增诊断信息：
- 后端收到开始/音频片段后返回独立回执，页面显示连接状态及已收到的录音秒数。回执不会覆盖转写文字，也不参与文字结果的版本比较。
- 开始提交后 15 秒仍无任何后端回复，会释放麦克风并提示连接问题。
- 停止后仍使用 90 秒等待上限；超时区分“未收到完整录音回执”与“已收完整录音、识别结果未返回”，不把它们统称为模型故障。
- LUX 终端新增 `[voice]` 阶段日志：接收阶段、累计秒数、最终识别开始、完成状态和耗时。不记录录音内容、识别文字或账号资料。

你此前的本地模型检查已成功。本次无需重装或重新下载模型；覆盖文件、重启并刷新即可。

## 使用方式

1. 点击原输入栏旁的“语音输入”，允许使用麦克风后直接说话。
2. 按钮变为“结束说话”；输入栏下只出现简短提示和正在识别的文字。
3. 再点一次结束。最终转写完成后，文字自动追加到原输入框，临时提示收起。
4. 在原输入框核对、修改文字，再自行发送。语音不会自动发送任务。

这次采用点击开始、再次点击结束，不需要一直按住按钮。录音期间仍可手动编辑原输入框；追加时读取最新草稿，保留已有内容。重复或过期结果不重复插入。输入长度不足时保留原草稿，识别文字留在下方供复制。安全检查拒绝的文字不展示或填入。

本包包含语音功能所需的兼容文件及之前的导航高亮修复，可直接覆盖原上传版本，也可以覆盖上一版语音补丁。不会包含或替换你的 `.env`、账号、业务数据库和模型缓存。不是完整独立项目，必须覆盖到原项目中。

## 行为与限制

- 保留本地 faster-whisper 识别；不会改用微信接口或浏览器云端语音服务。
- 约每 2 秒提交一段声音，阶段文字显示在输入栏下；停止后用完整已接收音频校正并填回输入框。2 秒不是保证的出字延迟，实际速度取决于模型、CPU、排队和网络。
- 使用支持 AudioWorklet 的现代浏览器，地址需为 localhost / 127.0.0.1 或 HTTPS，并允许麦克风。
- 接近 2 分钟自动停止，服务端维持 120 秒上限。切换主导航或隐藏页面会结束录音；离开页面会释放设备。
- 正常停止会提交不足 2 秒的最后一段；设备或网络异常不能保证音频恢复。最终识别等待超过 90 秒会解锁重试，区分音频回执缺失与后端识别结果超时，忽略该次晚到结果，已有预览可复制。
- 原上传音频入口按本次要求移除；原有附件上传和文字发送功能保留。
- 默认继续使用已经配置的本地模型；首次缺少模型时需运行安装脚本。模型及 Windows 安装过程未在本次环境实测。
