# 里程碑 B 真机测试方法（本地 TTS 与浏览器播放）

> 目标：用真实手机验证“回答朗读”能合成本地中文语音、在浏览器播放、可停止、
> 自动朗读默认关闭、唤醒后能快速播放预合成的“我在，请说”，并记录首音延迟与发音问题。

## 前置条件

1. 服务器已运行 `install_tts.ps1` 下载模型（`models/tts/kokoro-int8-multi-lang-v1_0`）。
2. `.env` 已设 `LUX_TTS_ENABLED=true`（默认音色 `zf_xiaoxiao`），服务已重启。
3. 手机能打开服务地址（公网 share URL 或局域网 IP），浏览器为现代版本。
4. 准备一段含数字/日期/电话/中英混合的问题，用于检验发音，例如：
   「请用一句话介绍第7次人口普查，并说明有困难拨打110或18601200909。」

## 功能验收

### 1. 朗读 / 停止

1. 在聊天框提问并等待回答完成。
2. 命令栏下方出现「**朗读 / 停止 / ☐自动朗读**」。
3. 点「**朗读**」：手机扬声器应播报该回答的中文语音，状态显示「正在朗读…」。
   - 若弹出「浏览器阻止了自动播放，点『朗读』即可播放」，点按钮后应能正常播放（移动端自动播放限制）。
4. 播放中点「**停止**」：应立即停止，不再出声。
5. 连续点多次「朗读」：只应播放最后一次的音频，旧音频不叠加、不迟到。

### 2. 自动朗读（默认关闭）

1. 刷新页面：自动朗读复选框**默认未勾选**。
2. 不勾选，提问并等待回答：不应自动出声。
3. 勾选「自动朗读」，再提问：回答完成后应自动播报。
4. 再次刷新：复选框回到未勾选（首版默认关闭，不跨会话记忆）。

### 3. 只朗读最终通过检查的回答

1. 提一个触发红线被拒的问题（如要求输出密钥/用户原文）：界面显示「🚫 …」，此时点「朗读」应提示「还没有可朗读的回答」而不是读别的内容。
2. 正常回答的朗读内容应**不包含** Markdown、代码、链接、来源列表，也不读出「已脱敏 N 处」等提示前缀。

### 4. 预合成“我在，请说”

1. 点「语音助手」开启，等状态变为「已就绪，喊“小安小安”唤醒」。
2. 说「小安小安」：应尽快听到「**我在，请说**」（预合成语音，不再是纯提示音）。
3. 若 TTS 未就绪，应回退为提示音（不静默失败）。

## 记录项

### A. 首音延迟

- **朗读延迟（人工计时）**：回答渲染完成 → 点「朗读」→ 到听到第一个字，计 5 次取平均。
- **唤醒应答延迟**：说「小安小安」结束 → 到听到「我在，请说」第一个字，计 5 次取平均。
- **冷启动 vs 预热**：重启服务后第一次朗读（含模型加载约 2 秒）与后续朗读各测一次。

### B. 发音问题

用含数字/日期/电话/中英混合的句子试听，逐条记录：

| 样本 | 预期 | 实测（是否读对/读错成什么） |
|---|---|---|
| 第7次人口普查 | 读“第七次”，不丢数字 | |
| 拨打110 | 读“幺幺零”或“一一零”，不跳过 | |
| 18601200909 | 逐位读出，不跳过 | |
| 2025年6月18号 | 读“二零二五年六月十八号” | |
| 真诚热爱 / 机器学习 | 中英混读自然 | |

### C. 失败与迟到

- 断网后点「朗读」：应提示合成/加载失败，不卡死发送按钮。
- 长回答（超过约 2000 字）：应只朗读截断到句末的部分，不整篇长篇朗读。

## 回传结果格式

```
朗读：首音延迟 冷启动__ms / 预热__ms；连续朗读是否叠加 __
停止：能否立即停止 __
自动朗读：默认是否关闭 __；勾选后是否自动播报 __
唤醒应答：听到“我在，请说”延迟 __ms；是否回退提示音 __
发音：数字 __ / 日期 __ / 电话 __ / 中英混合 __（逐条问题）
失败与迟到：断网提示 __；长回答截断 __
备注：（音色是否自然、是否需要调语速/换音色、特定浏览器表现）
```

结果回来后，再决定是否换音色（`LUX_TTS_VOICE`）、调语速（`LUX_TTS_SPEED`）或评估 int8 与 fp32 的取舍，然后进入里程碑 C（唤醒 → 提问 → 回答 → 语音播报闭环）。
