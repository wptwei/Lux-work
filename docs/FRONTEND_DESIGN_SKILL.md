# FRONTEND_DESIGN_SKILL.md

> LUX H区安保本地 AI 工作台的前端设计、实现与验收规范。所有后续 UI 改造必须遵循本文；异常事件处置 Agent 是首个样板页。

## 1. 设计目标与不可违反的约束

- 面向安保同事的日常业务工具，优先清晰、可靠、可读、可操作，不追求炫技式视觉效果。
- 视觉基调：深海军蓝企业风、低饱和蓝色主操作、克制的青绿色安全强调色；避免大面积霓虹、模糊光晕、强渐变和过度动画。
- 保留 Gradio 作为现有前端技术栈，不因视觉优化重写业务逻辑或制度匹配引擎。
- 不将模型建议伪装为已执行的业务动作；风险等级、紧急程度和人工确认状态必须清晰区分。
- 不以“代码已修改”代替验收。没有实际运行、交互测试或截图证据时，必须明确标记未验证。

## 2. 当前前端架构

```text
app.py
  ├─ Gradio Blocks / Tabs / Row / Column / 表单组件与事件绑定
  ├─ 自定义 HTML 使用具名业务类（例如 .incident-flow、.incident-result）
  └─ core/ui_theme.py 读取统一样式
       └─ frontend/lux.css 设计令牌、组件样式、状态、响应式规则
```

- `frontend/lux.css` 是唯一 CSS 源文件。
- `core/ui_theme.py` 只负责加载样式并暴露兼容导入名，不在其中复制 CSS。
- `app.py` 不得再新增 `CSS = "..."`、`CSS += "..."` 或散落的视觉样式块。
- `frontend/HcopilotAurora.jsx` 是设计原型，不是当前 Gradio 运行入口；除非单独规划迁移，不得把原型状态当成线上实际功能。
- 组件的真实行为仍由 `app.py` 中的 Gradio 事件和后端函数实现。纯 HTML/CSS 的视觉按钮不得冒充可用业务功能。

## 3. 设计令牌

令牌统一维护在 `frontend/lux.css` 的 `:root` 中。需要新颜色或间距时优先复用现有变量，不要在页面中随意新增近似值。

| 类别 | 规范 |
|---|---|
| 页面背景 | `--lux-bg: #0d1420` |
| 主表面 | `--lux-surface: #111d2c` |
| 浮层表面 | `--lux-surface-raised: #162438` |
| 输入控件表面 | `--lux-surface-input: #0c1725` |
| 主边框 | `--lux-border: #2b3a4d` |
| 强边框 | `--lux-border-strong: #3a4e65` |
| 正文 | `--lux-text: #eef3f8` |
| 次级正文 | `--lux-text-secondary: #c2cedb` |
| 辅助信息 | `--lux-text-muted: #8c9bae` |
| 主操作 | `--lux-primary: #4b87c4` |
| 安全强调 | `--lux-accent: #72c0b7` |
| 成功 / 警告 / 危险 | `--lux-success` / `--lux-warning` / `--lux-danger` |
| 圆角 | 小 `8px`、中 `12px`、大 `16px`；导航容器最多 `18px` |
| 间距 | 以 `4 / 8 / 12 / 16 / 20 / 24px` 为基础步进 |
| 阴影 | 卡片使用轻量 `--lux-shadow-card`；避免多层发光和高强度阴影 |

### 字体层级

- 页面主标题：22px，行高约 1.3。
- 卡片标题：17–18px。
- 正文、输入内容：14px。
- 表单标签、主要按钮：13px。
- 说明文字、空状态描述：12px，行高约 1.6。
- 只有编号、状态缩写、装饰性英文标签可以使用 10px 左右字号；关键业务信息不得使用微小字号。

## 4. 样板页：异常事件处置 Agent

### 信息结构

1. 页面介绍：说明该页的用途与人工确认边界。
2. 处置流程：事实提取 → 制度匹配 → 条件校验 → 风险/紧急程度 → 人工确认与留痕。
3. 现场接报表单：事件类型、发生区域、现场状态、发生时间、现场描述和明确的提交/重填操作。
4. 研判结果：风险等级、现场紧急程度、制度匹配状态、可追溯条款、建议动作、待补充信息及人工确认提示。
5. 人工闭环：事件台账、责任人、人工决定、说明和提交反馈。

### 布局规则

- 宽屏：左侧接报、右侧结果，建议比例约 2:3；卡片顶部对齐，边框、内边距和标题间距一致。
- 1050px 以下：接报与结果纵向排列，不能强行压缩成两列。
- 680px 以下：流程步骤允许两列换行；表单与结果单列；结果指标改为纵向；按钮不得被挤出视口。
- 任何断点都不允许页面产生非预期的水平滚动；流程步骤如需横向滚动，必须是局部容器并有明确可见内容。
- 页面应自然纵向滚动，不得通过 `overflow: hidden` 锁死主内容。

### 状态规范

- **初始/空状态**：说明输入什么、点击什么、结果会出现在哪里；不使用空白大区域制造视觉噪声。
- **加载状态**：提交后必须有明确处理中反馈，防止重复提交；控件禁用状态需可辨识。
- **成功状态**：只显示后端确实返回的数据和状态，不推断业务动作已经执行。
- **错误状态**：说明问题和可采取的下一步，错误信息不得被深色背景吞没。
- **信息不足/低置信度**：明确列出待补充事实或转人工提示，不伪造制度条款。
- **危险/紧急状态**：颜色作为辅助信号，同时必须有文字标签；不能只靠红/黄/绿区分。
- **人工确认状态**：把 Agent 建议和现场负责人最终决定分开显示。

## 5. 组件与交互规范

- 按钮、输入框、单选项、下拉框、卡片和状态标签使用同一套边框、圆角、字体与间距。
- 主操作按钮每个工作区域最多一个；次要操作使用中性样式，危险操作不得与普通操作混淆。
- 所有可交互控件必须绑定真实事件；如果尚未接入（例如语音功能），明确标注“待接入”并禁用。
- 输入控件必须具备默认值/占位提示、焦点态和禁用态；错误时给出可理解反馈。
- 键盘焦点必须可见；保留 `:focus-visible` 样式。
- 尊重 `prefers-reduced-motion`，避免呼吸灯、漂移背景等非必要持续动画。
- 自定义 HTML 必须使用语义明确的业务类名；文案中对用户输入进行 HTML 转义，避免把用户内容直接拼接为不可信 HTML。

### Galaxy/Uiverse 组件转化原则

| 参考模式 | LUX 中的转化方式 | 不采用的做法 |
|---|---|---|
| Button 状态 | hover/active 通过边框、背景和轻微色差反馈 | 夸张弹跳、缩放、强发光 |
| Card 层次 | 用表面色、边框和轻量阴影区分层级 | 大面积玻璃模糊、重叠渐变 |
| Form/Input | 统一高度、占位文字对比度、清晰焦点环与禁用态 | 仅靠颜色表达错误 |
| Radio/Toggle | 选中态同时改变背景、边框与文字 | 难以辨认的低对比选中态 |
| Loading/Notification | 明确显示处理中、成功或失败文本 | 无意义的持续呼吸灯或装饰动画 |
| Pattern/Decoration | 只在能帮助理解结构时使用 | 与业务信息无关的网格、光晕和装饰图案 |

## 6. Gradio 工程约定

- 复用现有 `Blocks`、`Tabs`、`Row`、`Column` 与组件事件，不随意引入第二套前端运行时。
- 新组件优先通过 `elem_id` / `elem_classes` 建立稳定样式钩子；对 Gradio 内部 DOM 结构的选择器保持克制，并在升级 Gradio 后重新验收。
- 不依赖不稳定的内部 CSS 类或 `data-testid` 来承载关键布局逻辑；确需使用时必须在测试清单中注明。
- 主题颜色通过 `gr.themes` 与 CSS 令牌协调，不能同时维护两套互相冲突的主题定义。
- 保持 `requirements.txt` 与部署虚拟环境的 Gradio 版本一致；升级后必须重跑页面与交互验收。
- CSS 必须集中在 `frontend/lux.css`，按“令牌 → 基础组件 → 业务组件 → 响应式 → 打印/无障碍”组织。

## 7. 质量验收清单

### 运行与回归

- [ ] `python -m compileall -q app.py agents core tests` 通过。
- [ ] `python -m unittest discover -s tests -v` 全量通过。
- [ ] Gradio 应用可以启动并返回 HTTP 200。
- [ ] 登录、权限、制度匹配、事件台账和既有工作台功能没有回归。
- [ ] 不将业务原文或敏感数据写入日志/事件台账。

### 视觉与交互

- [ ] 1440×1000、1280×800、1024×768、390×844 视口检查。
- [ ] 检查水平溢出、纵向滚动、固定导航遮挡、按钮被裁切、卡片错位和输入内容不可读。
- [ ] 验证初始、加载、成功、错误、禁用、信息不足、低置信度和人工确认状态。
- [ ] 检查鼠标悬停、键盘焦点、按钮点击反馈和重复提交保护。
- [ ] 检查控制台错误和网络请求失败。
- [ ] 保存样板页桌面/移动截图，记录浏览器、Gradio 版本、视口和验收结果。

### 交付声明

只有在对应检查实际完成后才能勾选。若浏览器、模型服务或部署环境不可用，需列明阻塞项；不得把静态代码检查写成完整视觉验收。
