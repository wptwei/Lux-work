# LUX 周报 Agent v4.1：内容智能化修复版

本版本优先修复实际生成稿暴露出的三类问题：模型调用失败后被本地规则草稿替代、同一行混合素材分类错误、未经过质量检查的内容被导出。

## 本轮改动

- **模型真实参与创作**：第一阶段由模型生成结构化事实策划；业务页面逐页调用模型生成正文，降低小模型一次性生成整份长稿被截断的概率。封面、目录和结束页使用稳定模板生成。
- **不再静默降级**：模型连接失败、JSON 无效、关键事实漏分配或页面内容校验失败时，界面只保留事实/策划诊断，不自动把关键词兜底草稿当成正式正文。状态会标明失败阶段和原因，导出会被拦截。
- **更准确的素材分类**：按分号、明确章节标记、指标字段和日期事件拆分混合行；将“所服务 BU”等背景信息与本周工作区分；剔除“你帮我写”等混入素材的写作指令。
- **事实覆盖检查**：人力、运营、异常、已完成工作和下周计划等关键事实必须分配到业务页面，否则会要求模型修复策划。
- **内容质量闸门**：检查原始提示语、模板说明、待补充占位符、未确认统计周期、无来源数字/趋势/原因。
- **图表真实性检查**：只有检测到同一指标的本期/上期原始值才允许生成对比图表；校验图表标签和数值是否有来源。兼容历史素材中的 `9wk1 / 9wk2` 表格格式。
- **逐页 token 控制**：结构化策划与单页正文分别限制输出长度，避免整份周报一次输出超过本地模型的生成上限。

## 安装与运行

1. 备份当前 LUX 项目，停止工作台。
2. 解压 `LUX_V3_周报Agent_v4.1_仅需替换文件包.zip` 到项目根目录，保留原有目录结构。
3. 不覆盖 `data/`、`.env` 和个人模型配置。
4. 在 PowerShell 运行：

```powershell
python -m compileall -q app.py core tests
python -m unittest discover -s tests -q
python app.py
```

若项目使用虚拟环境，请使用该环境的 Python 解释器。

## 推荐使用方式

1. 输入或上传本周素材，统计周期尽量在“周报周期”字段中明确填写。
2. 点击“分析素材并生成周报”。先查看事实来源清单与页面策划，再检查生成正文。
3. 若模型失败，按状态提示检查 Ollama 服务、模型名称和输出配置；此时不会生成可导出的规则兜底稿。
4. 若正文含待补充项或用户指令，先在正文中修正后再导出。
5. 导出前核对图表、数字、现场图片和统计周期。

## 测试与验收边界

- 当前开发容器：`python -m unittest discover -s tests -q`，**128 项测试通过**；`compileall` 通过。
- 覆盖模型失败不自动兜底、逐页生成、事实分类、写作指令过滤、图表数据来源检查、质量闸门和导出拦截。
- 目前未连接用户 Windows 电脑上的真实 Ollama 服务；真实模型的速度、结构化输出成功率和最终 PPT 页面效果仍需在目标环境验收。
