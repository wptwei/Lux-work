# LUX V3 · 周报及文档 Agent（第一阶段）

本更新基于用户当前使用的「异常奖惩匹配精简版 V3」，不改变异常奖惩 Agent 的数据表和业务入口。

## 本次新能力

1. 导入 TXT/CSV/Word/Excel/PPT 等已支持的文件，或直接粘贴工作素材，填写可选统计周期。
2. 通过原有红线守卫调用当前模型，整理固定 P1—P8 安保周报；若本地模型不可用、或模型没有返回完整 8 页，提供明确标注【待补充】的本地草稿。
3. **输入素材与编辑后的周报草稿分开**，右侧草稿可以修改，避免生成后覆盖原始素材。
4. 预览 8 页完成情况并检查缺页、重复页、空白页与待补充数据；PPT 若内容过多会阻止导出并提示精简。
5. 周报可以分别导出 **可编辑 DOCX** 和 **可编辑 PPTX**。保留原有标准版、模板版与历史周报底版生成方式，以及本机 Word 转 PDF。
6. 每次导出使用独立文件名，并写入 `data/deliverables.db` 版本元数据，不保存用户的业务原始文本。

## 如何安装（推荐替换包）

1. 退出正在运行的 LUX 工作台；先备份项目文件夹，特别是 `data/` 和 `.env`。
2. 解压「仅需替换文件包」，将 `app.py`、`core/` 内更新文件复制到现有项目的**同名路径**，允许覆盖；新增 `core/weekly_report_agent.py`。`tests/` 与 README 亦可放入根目录。
3. **不要删除或覆盖** 现有项目的 `data/`、`knowledge/`、`.env` 和其他 Agent 文件。
4. 在 PowerShell 进入项目根目录运行：

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -q
python app.py
```

5. 在浏览器进入「交付中心」→「周报及文档 Agent」。左侧粘贴本周内容或导入文件，填写统计周期（选填），点击「生成八页周报草稿」。右侧逐页检查、编辑，然后点击「生成可编辑 Word」或「生成可编辑 PPT」。Word 转 PDF 使用原有单独入口。

## 系统边界（务必留意）

- 草稿是辅助整理，不是已审核周报；**不会凭空编造环比、人数或成效**。没有数据的内容标【待补充】。
- 模型不可用时，本地兜底按关键词进行初步分类，仅作可编辑提纲，并不会做深入语义总结。
- 标准版 PPT 上 P3/P4/P5 的部分图片和图表仍为原项目的**视觉占位符**，没有自动生成真实图表；需自行更新。
- 采用历史 PPT 底版时仅替换部分文本和表格，原有图片、图表可能保留旧数据；导出后必须核实，且底版要求刚好 8 页。
- 大批量记录不适合塞进固定八页 PPT：PPT 导出前会限制页面行数。若记录较多，可下载完整 Word，再挑选重点内容生成 PPT。
- PDF 转换仍依赖 **Windows + Microsoft Word**，不能保证所有系统都可用。
- 只有用户明确授权为本地模型/公司内网服务时，才应输入未经脱敏的敏感业务材料；公网模型要遵守现有数据红线，不应上传受控资料。
- 版本台账只记录文件元数据和路径；不会自动把周报推送到邮箱，也不会从业务系统自动拉取日报数据。

## 修改文件

- `app.py`：分离原始素材与周报草稿、编辑检查、Word 导出、PPT 导出文件版本隔离。
- `core/weekly_report_agent.py`：八页完整性检查、本地兜底草稿、可编辑 DOCX 生成、PPT 容量检查。
- `core/ppt_export.py`：修复 P6 只取前三条导致的工作事项遗漏；P4/P5 的 Key Message 去重；长文本自适应。
- `tests/test_weekly_report_agent.py`：专项回归测试。

## 验证

在当前开发环境中 `python -m unittest discover -s tests -q`：**102 项通过**；成功生成并渲染样例 8 页 Word 和 8 张 PPT。未测试用户 Windows 环境实际加载和公司模型运行，需本机验收。
