# LUX V3 制度原文链接补丁

## 使用效果

点击奖惩结果卡片中的“制度依据”文字，在新标签页打开对应制度 PDF，使用 #page= 页码定位。
示例：供应商无人陪同游走 → HD-KS-SW-010 / 6.5.1.2.4 → PDF第8页。
页码按PDF物理页编号，包含前置页，与正文页眉的印刷页数可能不同。
保留条款原文和奖惩说明，不增加前台表单。

## 安装

本包适用当前V3工作台，基于此前“具体条款展示”版本。它是增量补丁，不是完整工作台，不包含匹配引擎。

1. 停止原工作台，备份 app.py。
2. 将本包 app.py、core/policy_source_links.py、knowledge/policy_sources/ 下两份PDF覆盖/复制到原项目同名位置。
3. 重新启动原工作台，登录后进行匹配，点击结果中的“制度依据”。
4. 如原 app.py 已有其他后续修改，请按 app_原文链接.diff 合入4处变更，避免覆盖自己的修改。

PDF使用本机找到的原始文件，按字节复制，未修改内容：
- HD-KS-SW-010：版本4，10个PDF页。
- HD-KS-SW-011：版本6，19个PDF页。
文件已包含在本包中，不需要从企业微信缓存路径读取。部署时文件名应保持不变。

## 访问及异常处理

- 链接使用现有Gradio文件路由，沿用登录校验；未登录返回401。
- allowed_paths仅列出两份PDF的完整文件路径，不开放项目目录或后台数据库。
- 对应版本文件缺失时显示“对应版本原文未配置”，不生成失效链接；补齐后重启。
- 浏览器支持内置PDF阅读时可直接查阅并定位；页码定位由浏览器PDF阅读器处理。
- 此补丁只增加原文链接，未修改匹配算法；此前测试第13条的误匹配问题不在本包中修复。

## 本轮验证

运行 python -m unittest tests.test_policy_source_links -v，5项测试通过：
1. 两种制度的链接及页码正确。
2. 文件缺失、未知制度、错误版本不生成链接。
3. 引用文字转义及工作台挂载前缀正确。
4. 实际HTTP验证：未登录401；登录后两份PDF均返回200、application/pdf、inline，返回字节与原文件完全一致；访问项目代码文件被403拒绝。
5. 真实app.py回调输出可点击链接、原文，并写入一条后台记录。

已提取原PDF文本核对版本与目标条款所在页，并渲染检查供应商PDF第8页。未进行用户现有工作台的浏览器点击验证。

回滚：停止工作台，恢复备份app.py后重新启动。新增源文件与PDF可保留。
