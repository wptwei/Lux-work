# LUX H 区安保本地 Agent：v0.6—v1.0 路线图

## 产品定位

LUX 的近期目标不是成为无人值守的生产控制系统，而是成为安保二部可审计、可复核、可量化的本地办公协作台。优先做好“读材料、产出文档、辅助研判、人工确认”，再逐步连接只读数据源，最后才考虑带审批的写操作。

## 当前基础

- 已有本地模型与公网模型路由，并默认本地优先。
- 已有输入、文件、输出三段式红线检查与最小化审计日志。
- 已有岗位技能、提示词库、文件/OCR、周报 PPT、邮件确认与效能看板。
- 已有事件识别、风险评分、处置建议和报告归档的多 Agent 闭环。
- 已有 29 项自动测试，核心安全链路具备回归基础。

## 第一阶段：v0.6 可用性内测（1—2 周）

目标：让 3—5 名种子用户可以每天稳定使用，并能快速反馈问题。

### P0 必做

1. 会话与任务历史
   - 将对话、文件处理、PPT 导出和事件处置统一为“任务”。
   - 支持任务标题、创建时间、状态、再次打开和导出。
   - 默认不保存业务原文；由管理员配置保存期限和脱敏策略。

2. 模型运行状态
   - 增加模型在线、响应耗时、当前队列、最近错误和磁盘空间状态。
   - Ollama 不可用时给出可操作的恢复提示，不只展示异常文本。

3. 用户反馈闭环
   - 每次输出提供“可用 / 需修改 / 不可用”评价与原因选项。
   - 记录人工修改耗时，用真实数据校准“节省工时”。

4. 前端交互补强
   - 增加任务进行中、成功、失败三类统一状态提示。
   - 长任务支持取消；文件解析与 PPT 生成展示阶段进度。
   - 为周报、邮件、事件处置增加示例输入和一键填充。

### v0.6 验收指标

- 关键任务成功率不低于 90%。
- 页面连续运行 8 小时无崩溃。
- 典型周报从输入到 PPT 下载不超过 3 分钟。
- 红线拦截、文件检查、邮件二次确认全部通过回归测试。

## 第二阶段：v0.7 管理与治理（2—4 周）

目标：从个人工具升级为可在部门内受控共享的应用。

1. 身份与权限
   - 建立使用者、模板管理员、审计员、系统管理员四类角色。
   - 局域网部署接入企业统一身份；未接入前至少使用独立账号和强密码。

2. 配置版本化
   - 红线规则、岗位技能、提示词模板均增加版本号、变更人、审批人和回滚。
   - 配置变更先在测试环境验证，再发布到部门环境。

3. 数据与备份
   - SQLite 每日备份，明确保留周期，增加一键恢复演练脚本。
   - 上传文件进入隔离目录，任务结束后按策略自动清理。

4. 审计工作台
   - 仅展示元数据、命中规则、操作人、时间和结果状态。
   - 支持按日期、岗位、风险等级筛选和导出审计报表。

### v0.7 验收指标

- 任一用户只能访问其角色允许的功能。
- 规则和模板可在 10 分钟内完成回滚。
- 备份恢复演练可在 30 分钟内恢复服务。
- 审计记录不包含业务原文和密钥。

## 第三阶段：v0.8 质量评测（3—5 周）

目标：让“模型效果好不好”变成可重复衡量的问题。

1. 建立脱敏评测集
   - 每个岗位选择 20—30 个真实任务结构，生成脱敏标准样例。
   - 为事实准确性、格式完整度、行动可执行性、红线合规分别评分。

2. 自动回归
   - 模型、提示词或规则升级前自动跑评测集。
   - 关键指标下降超过阈值则阻止发布。

3. 输出引用与证据
   - 文件问答标注来源文件、页码或工作表位置。
   - 不能从材料确认的内容统一标记为“待补充”。

### v0.8 验收指标

- 关键岗位任务格式完整率不低于 95%。
- 事实性错误率控制在约定阈值内，并能定位到失败样例。
- 每次版本发布都有可比的评测报告。

## 第四阶段：v0.9 只读系统集成（4—8 周）

目标：减少人工搬运数据，但不让 AI 直接执行生产动作。

- 优先接入排班、巡检、门禁记录等只读接口或受控导出文件。
- 使用最小权限服务账号，接口调用有超时、熔断、缓存和审计。
- 任何外部数据进入模型前都经过字段白名单与红线检查。
- 页面提供数据新鲜度和来源标识，禁止把过期缓存误当实时数据。

## 第五阶段：v1.0 部门级正式版（视审批推进）

目标：达到可运维、可治理、可追责的部门级应用标准。

- Web 服务、后台任务、模型服务分离部署；引入可靠任务队列。
- 集中监控响应时间、错误率、资源使用率和安全事件。
- 正式接入写操作前，必须具备预览、人工审批、幂等键、撤销或补偿机制。
- 完成 IT 加固、漏洞扫描、DLP 评审、账号权限评审和灾备演练。

## 建议的下一开发迭代

建议立即启动 v0.6，按以下顺序实施：

1. 任务历史与状态模型。
2. 模型健康状态和可操作错误提示。
3. 用户反馈与真实工时采集。
4. 长任务进度与取消。
5. 10—15 条端到端 UI 测试。

完成这五项后再进行多人局域网试点。暂不建议直接连接门禁、监控控制或自动发送外部邮件。
