# LUX 文件库 LLM 智能匹配更新（2026-10-27）

## 使用效果

无需完整文件名或编号，可以描述想找的资料，例如：

- 你好，帮我找一下安保体系文件管理规范
- 帮我找一下员工评分的规定
- 帮我找一下资料归档的规定
- 有没有管理安保人员的相关文件

先按已有名称、关键词查找；未命中时，调用当前配置的 LLM 理解用途、简称和近义表达，并从真实文件目录选择候选。可能匹配到多份时展示候选下载链接，不将推测说成确定匹配。没有模型时准确名称和关键词检索仍可使用。

这次增加了真实的模型调用流程，不是只为几个示例添加同义词替换规则。具体匹配质量取决于本机模型和文件目录的信息质量。

## 更新

适用于已经安装简洁后台 PDF 文件库的 LUX。本包包含此前对话接入、口语修复，无需依次安装旧对话补丁。

1. 按 Ctrl+C 停止 LUX，备份本包将覆盖的同名代码文件。
2. 将 overlay 内的内容按目录结构覆盖到项目根目录。
3. 在项目目录运行 `.\start_web.ps1`，浏览器按 Ctrl+F5 刷新。
4. 确认当前配置模型可用，再用上面的模糊描述进行验收。

无需重装依赖或重新上传文件。默认沿用本机 Ollama 和现有 OLLAMA_MODEL 配置；只有项目本身启用了 external 模式才会使用现有外部提供方，并保留原有外发检查。

## 实现范围

- LLM 看到的是当前账号可访问文件的名称、分类和标签，不读取整份 PDF，也不获得原件路径。
- 正常关键词检索仍可匹配已建立索引的 PDF 正文。
- 模型返回候选编号，程序验证编号并生成真实下载地址；模型返回的链接或编造编号不会被使用。
- 模型处理结束后再次检查文件是否仍存在、仍可访问、仍为该最新版本。下载接口继续执行登录和文件访问检查。
- 找文件不再限定普通对话模式，已启用岗位技能也可使用。模型判断是写作等任务时回到原有对话流程。
- 为适配小模型，先在全部可见文件目录中按名称、分类、标签的文字重合排序，送入最多 20 个候选（元数据预算 2600 字符）；大文件库中零文字重合的同义描述仍可能遗漏，可补充主题关键词或标签。
- 本版不是全文语义索引或 PDF 内容问答，也不执行 OCR。扫描件也可以依据文件名和标签参与匹配。
- 模型请求沿用现有超时设置；失败会提示智能匹配不可用，准确关键词检索不受模型服务影响。

## 修改内容

- core/library_retrieval.py：新增模型辅助检索，目录候选排序、JSON 校验及可见性复查。
- core/pdf_library.py：新增按权限过滤的最新文件目录读取。
- core/library_chat.py：补充问候语前缀和“规定、规章”表达，保留原有直接下载回复。
- app.py：接入配置模型、外部模式检查、检索进度提示及普通任务回退。
- tests/test_library_retrieval.py：新增 10 项语义匹配流程、私有文件排除、模型错误、不合法编号和候选预算等测试。

## 验证结果及限制

285 项自动测试通过。Gradio 实际 HTTP 接口通过了上传、自然语言请求、候选下载、权限检查、回收站和恢复测试。模型部分使用本地 HTTP 模拟服务测试了真实 Ollama 适配器的 JSON 请求与候选结果处理；文件上传、数据库检索、登录和 PDF 下载使用真实组件。

当前测试环境没有运行你的 Ollama 模型，因此未验证你所用模型的实际语义匹配准确率，也未在你的 Windows 浏览器中实测。不能把模拟模型测试解释为真实模型已经正确理解所有例句。

本包不包含账号、业务原件、密钥、模型文件或测试模拟服务。既有上传简化与语音超时修复保留。
