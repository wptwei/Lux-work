# 周报 Agent 内容智能化与动态页数创作

## 目标

在保留 LUX V3 前端、事实来源追溯和其他 Agent 的前提下，将周报流程升级为：素材理解 → 内容分析 → 页面策划 → 正文创作 → 来源核验 → 动态 PPT 渲染。

## 参考依据

本轮分析了三份真实历史周报：
- 《H区八月第四周周报》：9 页，包含现场执勤影像、关键节点纪实、管控核心与执行等扩展页面。
- 《H九月第一周周报0905》：8 页，包含人力、运营看板、异常分析、重点工作和下周计划。
- 《H九月第二周周报0912》：8 页，延续主结构并更新当周运营/异常数据和事项。

共同视觉特征为 16:9、深蓝/蓝色标题、青色点缀、微软雅黑、白底商务布局、数据看板和现场照片。视觉配置已沉淀到 `config/weekly_report_style_profiles.json`。

## 动态页数原则

- 页数不再固定为 8。模型按本期素材决定页面数量，通常 6—12 页即可，不强制；技术边界为 3—20 页。
- 常见页面类型：封面、目录、人力、运营看板、异常分析、本周重点工作、现场影像、关键节点、管控执行、下周计划、摘要、专题页、结束页。
- 材料少时减少页面；事项丰富时拆分页面；目录和结束页均可选，不为凑页数添加空白页。
- 页面标记采用 `## P1 [type:cover] | H区安保周报`，页码连续，标题在竖线后。

## PPT 创作模式

- **智能创作（自适应页数）**：使用内置的 H 区历史风格生成可编辑 PPT。
- **历史周报参考创作**：从上传历史 PPT 提取主题/母版，并只复用封面全页背景图作为固定视觉资产；清空旧页面，按本期页面策划重新生成，不沿用旧数据页或现场证据照片。
- **空白模板**：保留上传 PPT 的主题/母版并重新生成动态页数内容。
- 旧的“历史周报底版”接口保留为兼容模式，仅适用于模板页数与文稿页数一致的场景。

## 事实与质量约束

1. 数字、日期、趋势、原因和结果必须有素材依据或经过验证的计算。
2. 仅在存在可比的结构化数据时生成图表；没有数据时不虚构图表。
3. 历史照片不冒充本期照片；缺少本期图片时显示待补充占位并提醒用户。
4. 检查页码连续性、空白页、过长内容、未替换占位符、旧数据残留和图表更新情况。
5. Word 与 PPT 按实际页数导出。

## 验收重点

- 至少验证 4、6、8、9、12 页等不同页数。
- 以三份真实历史 PPT 为参考，检查主题/母版、封面背景、标题和动态页码。
- 验证旧页面数据和旧现场照片没有被复制到新周报。
- 在 Windows + Ollama 真实环境验证模型策划、导出和页面显示。
