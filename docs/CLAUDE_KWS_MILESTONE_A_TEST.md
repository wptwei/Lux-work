# 里程碑 A 真机测试方法（网页前台中文唤醒）

> 目标：用真实手机验证浏览器本地 KWS 能唤醒、少误触发、延迟可接受。
> 全程唤醒检测在手机浏览器本地完成，**未唤醒时不上传任何环境录音**。

## 前置条件

1. 服务已部署并启用 `LUX_VOICE_DIALOGUE_ENABLED=true`（服务器本地 `.env`，已生效）。
2. 手机能联网（公网 URL）或与服务器同一局域网（LAN IP）。
3. 手机浏览器为现代版本（Chrome / Edge / Safari 16+ / 手机自带浏览器），需支持 AudioWorklet。
4. 手边有一块秒表 / 第二个手机计时，用于端到端延迟测量。

## 开启语音助手

1. 手机浏览器打开服务地址（公网 `https://<share_url>`，或局域网 `http://<服务器IP>:7861`）。
2. 登录账号。
3. 点命令栏的「**语音助手**」按钮（按钮文案会变为「关闭语音助手」）。
4. 首次点击浏览器会请求**麦克风权限**——点允许。
5. 状态提示变为「已就绪，喊“小安小安”唤醒」即进入**待唤醒**状态。
   - 若提示「麦克风需要 localhost 或 HTTPS」：说明当前地址不是安全上下文，需改用 HTTPS 公网 URL 或 localhost。
   - 若提示「不支持 AudioWorklet」：换用较新的浏览器。

**每次点「开启」都会清零本机计数，作为一次新的测试会话。**

## 三个验收项与记录方法

页面状态区在首次命中后会显示一行小字指标，例如：
`命中 3 次 · 延迟 均42ms·最近38ms · 待唤醒 95s`

### 1. 唤醒成功

- 手机离嘴约 30–60 cm，清晰说一遍「小安小安」。
- **预期**：听到一声提示音，状态从「已就绪」变为「我在，请说」→「正在聆听…」，约 8 秒后自动回到「已就绪」。
- **记录**：说 10 次，看「命中」计数是否 ≈ 10。漏掉的次数记下来（漏报）。

### 2. 误触发

三种受控场景，各保持 **60 秒**，期间**不要说**唤醒词，看「命中」计数是否保持不变：

| 场景 | 做法 | 预期 |
|---|---|---|
| 静音 | 不说话，保持安静 | 命中不增加 |
| 无关语音 | 正常聊天 / 念与“小安小安”无关的话 | 命中不增加 |
| 环境噪音 | 放音乐、翻纸张、键盘声等 | 命中不增加 |

**记录**：任一场景中每出现 1 次命中 = 1 次误触发，记下发生在哪个场景、大概时间。

### 3. 延迟

- **检测延迟（自动）**：直接读页面小字的「延迟 均Xms·最近Yms」。这是“音频喂入→命中回调”的流水线延迟，用于确认模型推理不卡顿。
- **端到端延迟（秒表）**：一人说「小安小安」，说完的瞬间按秒表，听到提示音的瞬间停表；测 5 次取平均。这是用户真正感知的“喊→应”延迟。

## 控制台日志（可选，用于复核）

手机端不方便看控制台时，可用桌面浏览器远程调试同一 URL（Chrome DevTools / Safari Web Inspector），
在 Console 里能看到每次事件的 JSON 时间戳：

```
[voice-assistant] enable  { at: "...", state: "loading" }
[voice-assistant] armed   { at: "...", state: "armed" }
[voice-assistant] hit     { at: "...", count: 1, latencyMs: 42, detections: 1, state: "armed" }
[voice-assistant] wake    { at: "...", state: "acknowledged" }
[voice-assistant] disable { at: "...", state: "disabled" }
```

`hit` 的 `at` 时间戳可用于事后对照误触发发生的时刻。

## 回传结果格式

```
唤醒成功：说 10 次，命中 __ 次，漏报 __ 次
误触发：静音 __ 次 / 无关语音 __ 次 / 环境噪音 __ 次（各 60s）
延迟：检测延迟 均__ms 最近__ms；端到端 平均 __ms（5 次）
备注：（例如提示音是否清晰、是否需要凑近说、特定浏览器表现）
```

结果回来后，再决定是否调整唤醒词阈值/冷却时长，然后进入里程碑 B（TTS）与 C（ASR→对话→TTS 闭环）。
